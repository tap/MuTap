## Split rule

Assignment is by rule per source — a keyed hash (`kws_audio.assign_split`) with the committed
salt `mutap-kws-speech-commands-bringup-2026-09-09` and fractions train = 0.8, dev = 0.1, eval = 0.1 — or a source's official split where one
exists. The key per source:

| source | kind | split key |
|---|---|---|
| speech_commands_v0.02 | speech_commands_v2 | the official hash split: validation_list.txt → dev, testing_list.txt → eval, the rest train; key = the speaker hash before `_nohash_` (the same key the official lists were drawn by) |
| openslr_17_musan | musan | noise and speech partitions: file id; music: the artist/composer column of the subset's ANNOTATIONS where present, else file id — music is its own split axis, artist-disjoint |
| openslr_28 | openslr_28_simulated | room id (simulated RIR files, train / dev; the hold-out's rooms are real) |
| speech_commands_keywords | keyword_list | no audio; not split |

**Client-id approximation.** The splits are client-id-disjoint and clip-id-disjoint per source
by the keys above. That is an approximation of speaker-disjoint: a person with two client ids
(or two Speech Commands speaker hashes) can appear on both sides. No demographic column (age,
gender, accent) is copied from any source; the split key is the only per-person field held.
`verify_splits.py` enforces the five rules R1–R5 over this lock.

## Labels

For every positive the keyword end sample *e* in the dry source is the end of the last
10 ms window within 40 dB of the loudest, propagated
analytically through speed, RIR onset and stream offset (never re-trimmed after augmentation)
and stored as a 16 kHz sample index; its hop index is ⌊*e*/160⌋. Tolerance
*T* = 3 hops (manifest value; a target until the full build measures the trim
rule's spread across the length-scale draws, M4b); M5's hit window is [*h* − *T*, *h* + 20 + *T*].

## Augmentation

Frozen into the store under seed 1; every draw is a function of the seed and the clip id
alone (`kws_audio.draw_rng`), so the lock does not depend on `--jobs`.
*K* = 2 draws per positive, one clean plus *M* = 1 noisy
per negative, dry share 0.25; ranges: SNR [0.0, 20.0] dB, gain [-6.0, 6.0] dB,
speed [0.9, 1.1], RT60 [0.2, 1.0] s, microphone model `none`. Positives are
featurized embedded in 2 s of same-split negative material with one `reset()` per
mixture; a positive's RIR and SNR noise are applied over the whole mixture (context and keyword),
a negative's over its whole clip. Eval clips are never augmented.

## Resampler

One resampler for every source and for TTS output: `scipy.signal.resample_poly` with window (kaiser, 5.0),
scipy 1.18.1 (the lock's toolchain), resampler id
`resample_poly-1.18.1-kaiser-5.0`. The shipping `decimate.h` is never in the training path.

## Hold-out: repository privacy statement

Distinct from the runtime privacy statement (plan §5). The hold-out talkers' audio stays out of
git: it lives as FLAC under `<store>/holdout/` or as a private release asset. The repository
commits only the record, `holdout.json`. A row there holds, per utterance: the sha256 of the FLAC
file, the talker's pseudonym, the microphone path, distance, SNR, phrase, endpoint sample and
consent-form version — no audio, no form, no name. A hash reveals nothing without the file it
was computed from: it cannot be inverted, and it identifies a recording only to someone who
already holds that recording. Per talker the record holds a pseudonym, the consent-form version
and the permitted uses; signed forms live off-repo, referenced by pseudonym and form version.

**Withdrawal.** A talker withdraws by request; the files are deleted from the store and any
release asset, their rows are dropped and `holdout.json` re-versioned, the `holdout` source's
sha256 (the hold-out set id, the hash of the sorted per-utterance FLAC hashes) changes and with
it the manifest hash, and every figure measured against the old set id is re-measured, never
edited. **History limit:** the withdrawn rows — hashes and conditions only, never audio — stay
readable in the repository's history and in forks; the consent template says so.

This manifest carries no `holdout` source (M4c).
